Root-cause candidates to weigh against the trace (root_cause) — name the
one the evidence supports, or say the evidence doesn't distinguish:
- the loop variable is never updated on some path
- the loop variable is updated in a direction that moves away from the
  guard condition rather than toward it
- the guard condition depends on state the loop body doesn't change

Distinguish, based only on what the checker reported, between an
unwinding-bound violation (unwind limit reached without proving
termination) and a demonstrated non-terminating path. Don't default to
one if the report doesn't say which — reflect the ambiguity in
confidence if it matters.

evidence / execution_path: trace the loop variable's value across the
iterations shown in the trace, up to the point the checker stopped
verifying.

suggested_changes: phrase each item as something to verify (e.g. "does
this variable change on every path through the loop body?"), not as a
specific fix to the update or guard. Never state the corrected update
statement or condition.

example_fix: only populate if the trace shows enough iterations to
illustrate the *pattern* of the missing/wrong update. Use placeholder
names, not the student's own loop rewritten to terminate. Otherwise leave
empty and reflect the gap in confidence.

check_your_understanding: ask whether the loop variable moves toward or
away from the guard condition on each iteration, not about loops in
general.
