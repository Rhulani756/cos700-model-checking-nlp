Root-cause candidates to weigh against the trace (root_cause) — name the
one the evidence supports, or say the evidence doesn't distinguish:
- a missing null check before the dereference
- an unchecked return value from something that can return null (lookup,
  allocation, optional-returning function)
- a null check present earlier in the function that doesn't cover the
  path the trace actually takes

evidence / execution_path: trace the pointer from where it was last
assigned (or left uninitialized) on the failing path to the line where
it is dereferenced. Only describe a null check as "missing" if the trace
shows the failing path bypassing it — not because none is visible in the
snippet.

suggested_changes: phrase each item as something to verify (e.g. "check
whether every path to this line passes through a null check first"), not
as a specific check to add. Never state the exact conditional to insert.

example_fix: only populate if the trace shows clearly where the null
value originates. Illustrate the *pattern* (e.g. a generic null-check
guard) with placeholder names, not the student's own pointer name wired
into a working guard. Otherwise leave empty and reflect the gap in
confidence.

check_your_understanding: ask whether all paths to the dereference are
covered by a check, not about null pointers in general.
