Root-cause candidates to weigh against the trace (root_cause) — name the
one the evidence supports, or say the evidence doesn't distinguish:
- an off-by-one loop condition (<= vs <, or the reverse)
- an index computed from unchecked input or arithmetic
- a negative index reaching the access
- a size/bound value that no longer matches the buffer it describes

evidence / execution_path: trace the index's value from where it's set or
last updated to the line where the out-of-bounds access occurs. The bound
(array size, buffer length) only counts as evidence if it appears
explicitly in the source or trace — do not infer it from a declaration
you can't see.

suggested_changes: phrase each item as something to verify (e.g. "check
what value the index holds on the final loop iteration"), not as an edit
to make. Never state the corrected comparison operator or bound value.

example_fix: only populate if the trace shows both the index expression
and its update rule with enough certainty to illustrate the *pattern*.
Use generic variable names (e.g. i, n), not the student's own identifiers
combined into a working version of their loop. Otherwise leave empty and
reflect the gap in confidence.

check_your_understanding: ask about the relationship between the index
and the bound at the exact point of failure, not about arrays in general.
